## omerfsen.nvkr.nvkr_build

### Entry point `main`

Build everything an NVKE management cluster needs with NVKR.

| Variable | Type | Default | Description |
|---|---|---|---|
| `nvkr_build_registry_name` | str | `nvkr-registry` | Registry container name. |
| `nvkr_build_registry_image` | str | `registry:3.1.2@sha256:38907510915c3f1604c7e83d6ab602ab3020d092f73bdaed8696773693ff768c` | Registry image, pinned by digest. A container on another image or address is replaced; its data is kept. |
| `nvkr_build_registry_bind` | str | `127.0.0.1` | Address the registry listens on. Loopback: Runs publish over plain HTTP without credentials. |
| `nvkr_build_registry_port` | int | `5000` | Registry port. |
| `nvkr_build_registry_data_dir` | path |  | Registry storage. Defaults to `<nvkr_home>/registry`. |
| `nvkr_build_attempt_suffix` | str | `01` | Last part of every attempt name. NVKR attempts are immutable: after a failed attempt set a new value to start another. |
| `nvkr_build_attempt_suffixes` | dict | `{}` | Attempt suffix per Run, by input set name (`hello`, `nvke-components`, `nvke-os-amd64`), overriding `nvkr_build_attempt_suffix` for that Run only. |
| `nvkr_build_jobs` | int | `4` | Producer jobs per Run (`--jobs`). |
| `nvkr_build_timeout` | int | `21600` | Wall-clock limit for one Run, in seconds. |
| `nvkr_build_log_dir` | path |  | Run logs. Defaults to `<nvkr_home>/logs`. |
| `nvkr_build_components_platform` | str |  | Platform of nvkectl and the two seed-cluster images. Defaults to the build hosts, `linux/<nvkr_arch>`. |
| `nvkr_build_verify_reference` | str | `""` | Release to check, `repository@sha256:...`. |
| `nvkr_build_verify_outputs` | list | `[]` | Output names to pull and check. |
| `nvkr_build_verify_record` | dict | `{}` | The producing Run's lifecycle record; when set, every output digest must equal what that Run observed. |
| `nvkr_build_verify_dir` | path |  | Verified pulls land in `<dir>/<release digest>/<output>`. Defaults to `<nvkr_home>/verified`. |
| `nvkr_build_run_scope` | bool | `True` | Start every Run in a transient systemd scope with CPU accounting, then drop to nvkr_user with runuser. NVKRs local VM admission reads cpu.max in every cgroup up to the root and fails where the cpu controller is off, as in a systemd user managers app.slice (tmux, desktop terminals). |
